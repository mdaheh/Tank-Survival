## Инструкция для Исполнителя

1. **Маршрут.** Задачу выдаёт человек по ID. Файл правил выбирается по полю `Исполнитель`: `Стандартный` → `STANDART_EXECUTOR.md`, `Усиленный` → `HEAVY_EXECUTOR.md`. Чужая метка — не твоя задача: остановись и сообщи.
2. **Порядок.** Порядок выполнения = порядок перечисления в секции фазы. Зависимости `→` обязательны к закрытию: задача не начинается при незакрытой зависимости.
3. **`Evidence` обязателен.** После проверки заполни строку `- **Evidence**: ожидалось → наблюдалось → как наблюдал`. Без неё `[x]` не ставится и счётчик не увеличивается. «Компилируется» и «проверка статическим анализом» доказательством не являются.
4. **Закрытие.** `[x]` в поле `Готово`, пересчёт счётчика в шапке, отклонения — строкой `- **Заметки**: …` сразу под `Готово`.
5. **Статусы.** `[ ]` — не выполнено; `[x]` — выполнено с `Evidence`; `[-]` — снята/замена (в счётчик не входит).
6. **Отступления запрещены.** Имена классов, способ интеграции и порядок берутся из задачи и `architecture_analysis.md`. Нужно иначе — верни задачу Архитектору с комментарием.
7. **Ограничения обязательны. Общие правила WebGL:** сцена никогда не перезагружается; в `Update/FixedUpdate` — ноль аллокаций (строки, LINQ, `GetComponent` в цикле, `Find*`, new-коллекции) и дорогих вызовов; 100–200+ врагов на экране — норма; числа — через ScriptableObject/Inspector; комментарии там, где логика нетривиальна.
6. **Принцип смоук-теста фазы (важно).** Смоук-тест проверяет ТОЛЬКО уже реализованное и оформляется двумя блоками:
   - **«Проверяется»** — пункты, которые обязаны работать, с указанием задачи-автора (например, «спавн собранного танка (T003/T058)»);
   - **«Ожидаемо не работает»** — механики будущих фаз, перечисленные с номером фазы; в этих пунктах статус ❌ **запрещён** (это не провал).
   Смоук-тест НЕ тестирует нереализованные механики: если для пункта нет задачи-автора в этом файле — это ошибка постановки, верни пункт Архитектору. Смысл теста — **регрессионный барьер**: (а) раньше работавшее не сломалось; (б) фундамент следующих фаз действительно работает. Скрытые null-ссылки не ломают компиляцию и не всегда дают исключения, но блокируют все последующие задачи (пример: ссылка на FBX вместо префаба — ни одной ошибки, но 5 задач встали).
8. Если симптом проявляется в рантайме — **сначала источник данных**: какой ассет/префаб/ссылку подставляет код и **какое поле отвечает за состояние**; затем структура, затем код (разбор T052 — в его заметках, первопричина T024 — `architecture_analysis.md` §11). **Результат поиска по коду — не доказательство**: индекс в этой среде не видит `Assets/Tank Survival/Scripts/**`; подтверждай чтением файла или MCP-инспекцией.
9. **Буксует — возвращай.** Признаки: 2 неудачные попытки по одной задаче, повторяется одна и та же ошибка, нужен файл вне «Файлов» задачи. Форма отчёта — в файле правил своего маршрута (раздел «Если буксует»). Менять постановку самостоятельно запрещено.
10. **Гейт Архитектора.** Закрыв смоук-тест фазы и **минимальный сквозной прогон**, исполнитель не начинает следующую фазу сам — ждёт подтверждения Архитектора по фактам, привязанным к `commit hash`.
11. **Ассеты — только через MCP.** Правки `*.prefab`/`*.unity`/`*.asset`/`*.inputactions`/`*.controller`, сцены и инспектора выполняются MCP-инструментами. Запрещены: правка текста файла, чтение YAML как источника данных, создание/правка `*.meta`, выдуманные `guid`. Порядок: инспекция состава → правка → **подтверждение факта инспекцией**. Если MCP не может выполнить шаг — ТЗ человеку, задача не закрывается.
12. **Поле `MCP`.** В каждой задаче указано `требуется` или `не требуется`. При «требуется» до начала правок проверь дешёвым read-вызовом, что мост отвечает.
13. **Бюджет MCP.** T1 ≤4 · T2 ≤8 · T3 ≤15 вызовов; один вход в Play Mode (второй — только с обоснованием в отчёте). Группы инструментов — `.clinerules` §4.
14. **`git`.** Коммит — часть задачи (агент **или** человек): `git -c core.pager=cat add -A -- <свои файлы>`, затем `git commit -F Temp/msg.txt` (сообщение файлом в UTF-8 — иначе кириллица искажается в аргументах PowerShell; одна задача = один коммит, `T0xx: …`). `git status`/`log`/`diff` в терминал как проверка **запрещены** — вывод может не вернуться: пиши в файл внутри игнорируемого `Temp/` и читай файл. Факт коммита подтверждается чтением `.git/logs/HEAD`. Чужие изменения не коммитить; разрушительные команды (`reset --hard`, `checkout --`, `clean`) запрещены всегда. Найденное в рабочем дереве чужое изменение (например, перезаписанный Unity ассет) — не коммитить, зафиксировать в «Заметках».
