## Инструкция для Исполнителя

1. Выполняй задачи по порядку номеров (порядок = приоритет). Зависимости отмечены `→`: задачу нельзя закрывать при незакрытых зависимостях.
2. После закрытия задачи: поставить `[x]` в поле `Готово`, увеличить счётчик в шапке. Отклонения фиксировать строкой `- **Заметки**: …` сразу под полем `Готово` (создавать поле заранее не нужно):
   - Фактические отклонения от постановки — описание, что не совпало.
   - Возврат Архитектору (буксует / неясно / невозможна) — краткая причина; это сохраняет контекст для следующей сессии Исполнителя.
3. Отступления от `architecture_analysis.md` (имена классов, способ интеграции, порядок) запрещены — верни задачу Архитектору с комментарием.
4. Ограничения задачи обязательны. **Общие правила WebGL:** сцена никогда не перезагружается; в `Update/FixedUpdate` — ноль аллокаций (строки, LINQ, `GetComponent` в цикле, `Find*`, new-коллекции) и дорогих вызовов; до 100–200+ врагов на экране — норма; числа — через ScriptableObject/Inspector; комментарии там, где логика нетривиальна.
5. Последняя задача каждой фазы — смоук-тест: выполняется только после всех задач фазы и фиксирует результат.
6. **Принцип смоук-теста фазы (важно).** Смоук-тест проверяет ТОЛЬКО уже реализованное и оформляется двумя блоками:
   - **«Проверяется»** — пункты, которые обязаны работать, с указанием задачи-автора (например, «спавн собранного танка (T003/T058)»);
   - **«Ожидаемо не работает»** — механики будущих фаз, перечисленные с номером фазы; в этих пунктах статус ❌ **запрещён** (это не провал).
   Смоук-тест НЕ тестирует нереализованные механики: если для пункта нет задачи-автора в этом файле — это ошибка постановки, верни пункт Архитектору. Смысл теста — **регрессионный барьер**: (а) раньше работавшее не сломалось; (б) фундамент следующих фаз действительно работает. Скрытые null-ссылки не ломают компиляцию и не всегда дают исключения, но блокируют все последующие задачи (пример: ссылка на FBX вместо префаба — ни одной ошибки, но 5 задач встали).
7. Если симптом проявляется в рантайме — **сначала проверь источник данных** (какой ассет/ссылка подставляется), и лишь потом структуру. Диагноз без проверки ссылки на ассет считается гаданием (разбор кейса T052 — см. его заметки).
8. **Метки и маршрут.** Сложность задач T064+ — по шкале T1–T4 с обязательным полем `Обоснование метки`. Поле `Исполнитель` — метка маршрутизации для разработчика: Стандартный выполняет T1/T2, Усиленный — T3/T4. Если задача «буксует» (2 неудачные попытки / >45 мин без прогресса / повторяющаяся ошибка) — верни её Архитектору отчётом по форме из `.clinerules` (раздел «Эскалация и возврат задачи»), а не пытайся решать её бесконечно.
9. **Гейт Архитектора.** Закрыв смоук-тест последней задачи фазы, Исполнитель **не начинает следующую фазу сам** — фиксирует результат и ждёт подтверждения Архитектора.
10. **Чужая метка — не твоя задача.** Задачи с меткой `Исполнитель: Усиленный` Стандартный исполнитель не выполняет: если такая задача попала к тебе (по ошибке или в составе пачки) — остановись и сообщи «задача не моего маршрута». Самостоятельно «взять следующую» нельзя: задачи выдаёт человек, порядок приоритета действует внутри одного маршрута.
